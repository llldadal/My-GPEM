# 链接
链接是对多个 [ELF 文件](ELF文件.md)执行的过程，包含符号解析和重定位两个阶段

- 符号解析： 将不同文件间的相同符号关联起来
- 重定位：依据规则修正代码和数据中的地址引用；最终值可能是绝对地址、相对偏移，或留给动态链接器处理的重定位项

下面详细介绍这两个阶段(以普通.o文件为例)

## 符号解析
符号解析即是链接器将a.o与b.o之间的未定义符号和其定义关联起来的过程

符号解析时，不同的[符号类型（Bind）](ELF文件.md#symtab-符号表)会有不同的规则，具体如下：

- LOCAL： 只能关联到本文件
- GLOBAL： 可关联到其他文件，且只能有一个定义；在和WEAK重定义时，使用GLOBAL的定义
- WEAK：可关联到其他文件，可以有多个定义；与 GLOBAL 定义同时存在时通常选择 GLOBAL 定义。存在多个 WEAK 定义时，具体选择受链接器和输入顺序影响，不应依赖某个固定结果

每种符号的默认产生方式如下：
- LOCAL： static修饰的静态函数、静态变量为 LOCAL 符号
- GLOBAL：普通函数、全局变量为 GLOBAL 符号
- WEAK: 现代c/c++并不自动产生 WEAK 符号，但是可以由 ```__attribute__((weak))``` 属性指定

这里需要注意[暂定定义](暂定定义.md)与弱符号（WEAK）的区别：使用 `-fcommon` 时，暂定定义通常生成为 COMMON 符号；使用现代 GCC 默认的 `-fno-common` 时，则通常成为普通的 GLOBAL 定义。

## 重定位
重定位即链接器根据[重定位信息表](ELF文件.md#relatext-重定位信息表)的信息，修正代码和数据中的地址引用。具体规则会因重定位类型的不同而不同，感兴趣的读者可以自行查阅。

这里主要介绍一下不同类型的ELF文件重定位的大致知识点

### 可重定位目标文件 .o 和 静态库文件 .a
这俩一起讲，因为本质上.a重定位时也是以.o的形式参与的

静态链接器利用符号表和重定位信息处理这些输入文件。使得静态链接的符号地址在链接时固定

而需要动态链接的符号，保留动态重定位信息到运行阶段

**为啥要这样说呢，因为它们与动态库有很大的不同！！**

### 动态库文件 .so
运行时动态链接主要使用 `.dynsym` 动态符号表；`.symtab` 即使存在，也通常不会由动态链接器用于符号解析。动态库的代码和数据一般不会复制合并进可执行文件，而是在装载时映射，并通过动态重定位完成地址修正。

GOT 和 PLT 是 x86-64 ELF 中访问外部数据与函数的常见机制，但并非每个符号或每种架构都必须经过它们。

**GOT 和 PLT 由静态链接器建立，其中需要运行时解析的条目再由动态链接器处理**

**所以，需要参与运行时符号解析的符号必须出现在动态符号表中，仅存在于 `.symtab` 中通常不够**

## 合并
这是链接布局的收尾阶段。链接器会依据链接脚本把输入节放入输出节；同名输入节经常被放在一起，但也可能被拆分、丢弃或按规则重排，最终生成可执行文件、共享库或新的可重定位目标文件。
