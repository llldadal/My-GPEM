## 问题代码示例

## 报错提示（类似于）
```text
undefined reference to `common_units'
```

## 报错原因及分析
既然链接器直接告诉我们，有未定义的引用 `common_units`，那么大概率问题出现在[链接时的符号解析](../../知识点/链接.md#符号解析)阶段

_运行期也会有类似的问题，但是报错通常为：_
```text
undefined symbol
```

根本原因多样，但是直接原因明显：一个符号有引用但没有定义，导致符号解析失败（或者运行期动态链接失败）

下面详细分析其不同的根本原因

### 实际上的没有定义
那还说啥了，就是没有呗，物理意义上的没有

**但是需要注意，是否有定义看的是 [ELF 符号表](../../知识点/ELF文件.md#symtab-符号表)中的符号名，而不是源文件中的名字！！！**

比如有些初学者会把函数的不同重载当成同一个符号，实际上并不是。C++ 不允许只靠返回值区分重载；名称修饰通常还会反映命名空间、参数类型、成员函数限定符等信息，具体规则取决于所使用的 ABI。

下面只单独说一个特殊的问题

---
#### C 和 C++ 文件混合链接
在 C 语言中，ELF 符号名通常接近源文件中的变量名或函数名。例如：
```c
// add.c
int add(int a, int b)
{
    return a + b;
}
```
编译后其符号名一般也是
```text
add
```

但是在 C++ 中，为了支持函数重载，会对函数名进行名称修饰。例如，在采用 Itanium C++ ABI 的 GCC 或 Clang 中：
```c++
// add_2.cpp
int add(int a, int b);
```
编译后其符号名可能为：
```text
_Z3addii
```

所以在链接器看来，`add_2.cpp` 中引用的符号 `_Z3addii` 和 `add.c` 中定义的符号 `add` 根本不是一个东西，自然会报错。

```text
undefined reference to `_Z3addii'
```
